# r7-bloom-filter —— 缓存穿透 + 布隆过滤器

**tag**：`r7-bloom-filter`
**日期**：2026-10-10
**主题**：防**缓存穿透**——查询数据库中也不存在的 key。
**标准口径**：日志关闭；单机，相对对比；DB 负载以 **MySQL 自身 `Com_select`** 为准。

---

## 1. 什么是缓存穿透

查一个**缓存和数据库都没有**的 key（如伪造 `id=999999`）：
缓存永远不命中 → 每次都打到 DB。攻击者用海量不存在的 id 就能打垮数据库。

> 与击穿（r5）的区别：**击穿是"热点 key 刚好过期"；穿透是"key 根本不存在"。**

三种策略：

| 策略 | 做法 | 缺点 |
|---|---|---|
| `none` | 无防护，直接查库 | 每个请求都打 DB（穿透） |
| `null` | 缓存空值（"NULL" + 短 TTL） | 每个不存在的 key 仍要查一次库；大量随机 key 会挤占缓存 |
| `bloom` | 布隆过滤器先判存在性 | 有误判（只会误判"存在"）；新增数据要同步；不支持删除 |

---

## 2. 代码

- `GoodsBloomFilter`：**Redis bitmap** 实现的布隆过滤器（多实例共享一份）。
  - `m=100000` 位，`k=3` 个哈希位（splitmix64 + 双哈希 `h1+i*h2`）。
  - 启动时用现有商品 id 重建；`POST /api/goods/bloom/rebuild` 可重建。
- `GoodsPenetrationService`：三模式 `seckill.cache.penetration=none|null|bloom`。
- 接口：`GET /api/goods/{id}/pen`、`GET /api/goods/pen/stats`、`POST /api/goods/pen/stats/reset`。

## 3. 压测数据

**场景**：JMeter 随机请求 **不存在的 id 100000~100999**（1000 个），100/200/500/1000 并发，各 30s。
**DB 负载**：压测前后读 `mysql -e "SHOW GLOBAL STATUS LIKE 'Com_select'"` 取差值（空转基线 10s 增量 = 1）。

| 策略 | 并发 | 吞吐 | 平均 | P99 | **DB 查库次数(Com_select)** | DB/请求 |
|---|---:|---:|---:|---:|---:|---:|
| **none** | 100 | 22742/s | 3.6ms | 9 | **681069** | 1.0000 |
| none | 200 | 22261/s | 7.4ms | 15 | 666352 | 1.0000 |
| none | 500 | 22866/s | 18.0ms | 30 | 684636 | 1.0000 |
| none | 1000 | 22136/s | 10.2ms | 43 | 664584 | 1.0000 |
| **null** | 100 | 33407/s | 2.5ms | 5 | **1005** | 0.0010 |
| null | 200 | 28317/s | 5.9ms | 13 | 1181 | 0.0014 |
| null | 500 | 25159/s | 16.6ms | 29 | 0* | 0.0000 |
| null | 1000 | 27757/s | 30.1ms | 115 | 1070 | 0.0013 |
| **bloom** | 100 | 27706/s | 3.0ms | 7 | **0** | 0.0000 |
| bloom | 200 | 28182/s | 5.9ms | 14 | 0 | 0.0000 |
| bloom | 500 | 29857/s | 14.0ms | 24 | 0 | 0.0000 |
| bloom | 1000 | 27962/s | 29.8ms | 55 | 0 | 0.0000 |

> \* null-500 的 0 次：前几档已把 1000 个 id 的空值缓存住了（TTL 60s），所以这一档没查库。
> 布隆模式下应用记录 `bloomRejects` ≈ 83万~89万（每个请求都被拦下），`dbLoads = 0`。

---

## 4. 解读

1. **none**：每个请求都查库，`Com_select` = 请求数（~68万），DB 承受全部流量。
2. **null**：查库降到 **~1000 次**（= 不存在的 key 种类数），之后命中空值缓存。
   代价：1000 个空值也进了缓存；若攻击者用**海量随机 id**，缓存会被空值挤爆。
3. **bloom**：查库 **0 次**——不存在的 id 在布隆处直接返回，DB 完全无感。
4. bloom 吞吐（~2.8万/s）略高于 none（~2.2万/s），因为省掉了 DB 往返。

---

## 5. 结论 / 面试点

- 穿透的本质是「不存在的 key 绕过缓存打 DB」，**布隆过滤器用极小空间换掉全部无效查询**。
- 布隆过滤器三个必答点：**只会误判"存在"、不支持删除、新增数据要同步**（本实验用重建解决）。
- 生产常见组合：**布隆过滤 + 缓存空值**（布隆挡绝大多数，漏网的误判用空值兜底）。
- 与 r5/r6 一起构成完整缓存防护：**穿透(布隆) + 击穿(互斥/逻辑过期) + 雪崩(TTL 加随机) + 一致性(双删)**。

## 6. 遗留

- 布隆误判率未量化（本实验 m 很大，误判≈0；可缩小 m 观察误判）。
- 商品增删后需手动/定时重建布隆。
